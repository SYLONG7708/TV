# 聚玩來源適配與更新

一般 CMS、AppGet、XBPQ 與 XYQ 的回應格式不同。原本影視的雲端程序只會讀一般 CMS，以及少數寫死的 Spider，所以把其他配置網址直接加入，通常只能看到名稱，無法搜尋或選集。

本次在雲端加入相容層，把已驗證的來源轉為現有影視使用的搜尋索引與選集資料。使用既有影視授權版即可載入，套件名稱、簽章及授權流程不變。

## 使用

1. 關閉並重新開啟影視，等待雲端資料載入。
2. 開啟來源選單，搜尋「適配」，選取上述來源。
3. 搜尋片名，開啟作品後選集播放。雲端搜尋可使用已收錄片名；尚未補入的舊片會在後續更新逐步增加。

## 自動更新

整合既有 `update-lunatv-vod.yml`，每日臺灣／上海時間 02:00 起更新；GitHub 排程可能延遲。08:00、14:00、20:00 的觸發會檢查狀態，未到期則略過，失敗或過期才重試。電腦不需開機，不會在本機開啟視窗。

每輪讀取各分類前 2 頁，再向後補 4 頁，上限每分類 200 頁；每來源每輪最多處理 120 筆詳情，分配給舊片輪替刷新、新片補庫與缺漏重試，避免補庫期間停止更新連載。進度隨目錄保存；已完成分類仍讀取最新作品。缺漏與尚未處理的片目放入待辦佇列，佇列達保護上限時退回對應頁碼，避免略過作品。遇到重複頁、來源錯誤或媒體抽樣失敗會記錄原因並保留舊資料。200 頁的保護上限若先達到，完成旗標保持 false，需要調整上限才能繼續補入更深頁數。

目前播放器讀取一組選集，適配器會選擇集數最完整的一條直接播放線，保留該線所有選集。只在沒有直接播放線時，才依上游宣告的公開協定解析該線全部選集。平台觀看頁、需要登入或另有特殊播放器的內容會標示錯誤，不能當成直接影片加入。

## 維護

```powershell
npm.cmd ci --prefix tools/source-adapters --ignore-scripts --no-audit --no-fund
node --test tests/*.test.mjs
node tools/seed-adapter-vod.mjs --repoRoot . --refreshPages 1 --backfillPages 0
```

- 登錄清單：`sources/juwan-adapter-sources.json`。
- 正式排程入口：`tools/build-type3-spider-catalog.mjs`。
- AppGet 的物件設定不再被轉成 `[object Object]`，也不會因為共用 `csp_AppGet` 名稱而互相覆蓋。
- 配置中的公開傳輸設定在更新時從上游讀取；公開目錄不複製傳輸金鑰或裝置識別值。
- XBPQ 使用二次截取與常見播放清單容器，避免把首頁、導覽等連結當成選集。
- XYQ 支援 JSON、JSONP、DOM 與 `{SearchPg}` 搜尋頁碼。
- AppYs 與 drpy 宣告式規則也有相容模組；這次沒有把未通過實際完整流程的來源登錄為可用。drpy 中需要執行腳本的部分會回報 `runtime-required`，不會執行下載的任意程式。
- 上游失效、帳號驗證、地區限制、私有 JAR／Python 協定仍需個別處理。此相容層沒有宣稱整個聚玩網站的所有來源皆可使用。
